# Lime 场景配方

按教学关系选配方，可组合或只采用局部。颜色、字体与材料只由项目 `frame.md` 定义；共享运镜、读字、焦点与素材能力只按 `references/motion-direction.md`；具体物件仍按 `references/object-library.md` 取得。这些参考结构按本期内容调整；验证状态见对应 metadata。

## 1. 同一对象经过多站

适用：输入经过多个处理步骤，观众需要知道各步改变了什么。

输入：可追踪的核心对象、各站输入/处理/输出状态、必要标签和实际时间窗。站数服从内容。

建立相邻工作站与贯穿路径，让核心对象进入第一站；对象经过一站时，展示该站特有的处理变化，留下已经发生的结果；镜头跟随核心对象到下一站，邻站保持空间方向；终点拉远或重构图，呈现刚才走过的完整流程。对象可以是视频缩略图、样本、文件、信号或一项数据，其身份应能持续辨认。

参考：`samples/lime-36.jpg` → `lime-42.jpg` → `lime-45.jpg`，对应第一条约33–45秒。原片“模板/素材/动画/成片”换成本题所需步骤。若每站只是换标题而对象状态没变，回分镜补上处理事件。

## 2. 同一组平面对象展开空间

适用：比较平面与空间表达、解释层级、展示同一结构的另一种组织方式。

输入：同一组具有稳定 ID 的对象、初始关系、展开后的关系与需要突出的一项。

先把对象放在容易比较的平面排列中；保留对象内容和身份，逐步改变位置、朝向、遮挡与尺度，形成有原因的前后层；焦点交给当前对象，路径或局部动作解释它和其他对象的联系；到站保持文字清晰，可回到总览归纳区别。连续变化由本期同一条 seekable timeline 表达，不以切到另一组近似图伪装展开。

参考：`samples/lime-66.jpg` → `lime-73.jpg`，第一条约65–76秒。这是平面卡片的2.5D展开，换面或真实环绕按本期素材能力另行验证。只有本题需要层次时才采用空间展开。

## 3. 提炼、汇入、加规则、选中

适用：知识库、素材库、规则匹配、候选筛选等关系。

输入：来源、提炼出的成员、共同容器、选择条件、候选与本题可说明的结果。

从第一路来源提炼出可辨认的成员并汇入一个库；第二路来源以同样方式加入已有库，观众能看见成员累积；把场景条件连接到对应成员，说明规则如何建立；新输入进入规则入口，候选发生真实区分；保留唯一或多项真实结果，其余候选退居次要，收束到选择依据。结果数量由本题事实决定。

参考：`samples/workbench-64.jpg`、`workbench-78.jpg`，第二条约56–83秒。文件柜、齿轮、放大镜分别支持存储、规则运转和查找；换题后重新选合适物件。示意结果标明其演示性质，实际产品功能与准确率引用真实证据。

## 4. 一个稳定结构承接多份内容

适用：模板复用、批量产出、同一方法作用于多个案例。

输入：保持不变的结构、需要替换的内容、每份结果及其可比特征。

先建立一个结构及一份结果；保持结构和路径，让第二、第三份内容进入并产生相应结果；必要时让旧结果留在旁边形成可比序列；结束时把共同结构与结果组同时呈现，观众能区分什么稳定、什么改变。成员数量按事实与画面容量确定，来源不足时采用清楚标注的示意。

参考：`samples/lime-79.jpg`，第一条约77–81秒。让每次内容替换有对应的可见结果。

## 在本期落地

将所选配方和采用的参考范围写入既有 STORYBOARD 条目，与句子→可见事件→对象来源映射、时间窗、当前→下一注意对象、离站/经过/到站/阅读状态放在一起。按内容长度、对象数量和素材实际边界重算构图，不固定横移距离、站点数或时长。实现优先用既有 HyperFrames 能力，再围绕本题补局部动作；配方名不代替实现证据。

用参考的关键状态做设计对照，按现有 quality 合同检查机制与交接；换一组内容、重算落点和阅读窗后，才声称该本期实现具备替换复用能力。Lime 接入本身只提供风格、材料和可追溯配方，不升级现有关系组件的验证状态。
